# Phone workspace and PID lab

User authorized implementation and publishing in the 2026-10-10 request. Goal: change controls while seeing the response on a phone, and learn tuning versus valve defects.

Use the existing static HTML/JS app. A shared workspace keeps one selectable plot/diagram above a separate scrolling control area on phones. Operate exposes routine actions; Setup exposes model parameters; Learn retains explanations and references. Desktop uses adjacent observation and controls. Run demo resets a reproducible example, explains its stages, and automatically stops. Custom cancels automation and permits intuitive step buttons/sliders. Navigation and hidden documents pause everything.

Add a seventh PID module with Step test and Apply tuning stages. Use a normalized self-regulating FOPDT process (gain 1, time constant 20 s, delay 4 s by default), with independent OP, actual travel, true PV, measured PV, and SP. Defects: none, static/sliding friction, reversal clearance, slow valve, limited travel, measurement noise. Offer manual/auto, OP/SP nudges, load changes, reverse/direct action, and Honeywell-style A/B/C term placement. Implement an explicitly labeled noninteractive/ideal form, filtered derivative Td/16, conditional integration anti-windup, and tracked bumpless manual/auto transfer. Kc in %OP/%PV, Ti/Td in minutes; internal seconds. This is not a firmware emulator or an interactive/series PID.

Automated manual step: baseline 10 s, OP 50→60%, observe at least five time constants. Identify signed gain, delay and time constant from recorded 28.3/63.2% crossing times after settling. Never use hidden process constants as the estimate. Reject unresolved/small or clipped responses. Show defect/noise caveats. Recommend SIMC PI using lambda >= delay: Kc=tau/(abs(K)*(lambda+theta)), Ti=min(tau,4*(lambda+theta)), Td=0. Transfer estimates to tuning with a deliberate button; demonstrate SP and load changes in Auto with the chosen defect. Custom step recording and numeric model/tuning inputs remain available.

Preserve slow friction sweeps by recording at fixed simulated intervals rather than animation frame count. Use bounded histories that retain a complete slow cycle. Keep selection state accessible. No added runtime dependencies, backend, telemetry, or plant connectivity. Actual phone/browser QA remains unavailable in the current managed environment.
